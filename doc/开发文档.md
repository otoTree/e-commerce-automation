OZON-AI助手 - 开发技术文档

1. 系统组件职责

- 前端 (Frontend):
  - 职责: 渲染用户界面、处理用户输入、调用后端API、展示API返回的数据、管理客户端状态（如任务ID、加载状态）。
  - 不负责: 核心业务逻辑、数据存储、与外部服务（OZON, 1688, AI模型）的直接通信。
- 后端 (Backend):
  - 职责: 实现所有业务逻辑、提供RESTful API、管理数据库、与浏览器插件通信、调用AI模型和OZON平台API、任务管理与调度。
  - 不负责: UI渲染。
- 浏览器插件 (Browser Plugin):
  - 职责: 接收后端指令、在客户端浏览器环境中执行1688等网站的DOM解析和数据抓取、将抓取结果回传给后端。
  - 不负责: 业务逻辑、UI（除了必要的配置或状态指示）。

2. 核心工作流I: AI选品助手 - 技术实现

2.1 启动选品任务

- 前端实现:
  - 提供一个输入框，允许用户粘贴OZON商品URL或输入关键词。
  - 提供一个“开始分析”按钮。
  - 点击按钮后，调用 [API 1.1]。
  - 调用后，立即将返回的 taskId 存到客户端状态中，并显示加载动画/进度提示。页面进入“任务进行中”的状态。
- 后端 API:
  - [API 1.1] 创建选品任务
    - Endpoint: POST /api/v1/selection-tasks
    - 描述: 根据用户输入（URL或关键词）创建一个新的选品任务。这是一个异步任务的起点。
    - Request Body:
    - JSON
{
  "type": "url" | "keywords", // 'url' 或 'keywords'"value": "https://ozon.ru/product/..." // 如果type是'url'// "value": "Беспроводные наушники TWS" // 如果type是'keywords'
}
    - Success Response (202 Accepted):
    - JSON
{
  "taskId": "task_sel_a1b2c3d4",
  "status": "PENDING", // 状态: PENDING -> SCRAPING -> PROCESSING -> COMPLETED/FAILED"message": "任务已创建，正在准备爬取"
}
    - 后端逻辑:
      1. 创建任务记录，状态为PENDING。
      2. 解析输入，生成1688搜索关键词。
      3. 通过与插件的通信机制（见第4章），向插件下发爬取指令，并附上taskId。
      4. 更新任务状态为SCRAPING。

2.2 获取选品结果

- 前端实现:
  - 在任务进行中页面，使用taskId，每隔3-5秒轮询一次 [API 1.2]。
  - 根据API返回的 status 更新UI提示信息（例如：“正在爬取数据...”，“正在分析与排序...”）。
  - 当 status 变为 COMPLETED 时，停止轮询，获取 results 数组。
  - 将 results 渲染成商品列表，每个商品项包含图片、标题、价格、相似度，并提供勾选框。
- 后端 API:
  - [API 1.2] 查询选品任务状态与结果
    - Endpoint: GET /api/v1/selection-tasks/{taskId}
    - 描述: 获取指定任务的当前状态和最终结果。
    - Success Response (200 OK):
    - JSON
// 任务进行中
{
  "taskId": "task_sel_a1b2c3d4",
  "status": "SCRAPING" // 或 PROCESSING
}

// 任务完成
{
  "taskId": "task_sel_a1b2c3d4",
  "status": "COMPLETED",
  "results": [
    {
      "supplierProductId": "prod_1688_x1y2z3",
      "source": "1688",
      "title": "厂家直供TWS蓝牙耳机...",
      "price": "35.50",
      "imageUrl": "https://cbu01.alicdn.com/...",
      "productUrl": "https://detail.1688.com/...",
      "similarityScore": 0.92 // AI计算的相似度
    },
    // ... more products
  ]
}
    - 后端逻辑:
      1. 插件完成爬取后，会调用一个内部接口（见4.2），将数据与taskId一同提交。
      2. 后端收到数据后，更新任务状态为PROCESSING。
      3. 进行数据清洗、相似度计算、排序。
      4. 完成后，将结果存入数据库，更新任务状态为COMPLETED。
      5. 此API仅从数据库查询并返回任务的当前状态和结果。

2.3 成本核算

- 前端实现:
  - 允许用户勾选列表中的多个supplierProductId。
  - 提供一个文本输入框让用户填写物流需求（例如：“空运，10天到货”）。
  - 点击“核算成本”按钮后，收集所有勾选的supplierProductId数组和物流需求文本，调用 [API 1.3]。
  - 用返回的带有成本信息的数据更新UI列表，展示每个商品的预估总成本和物流方案。
- 后端 API:
  - [API 1.3] 核算带物流成本
    - Endpoint: POST /api/v1/costs/calculate
    - 描述: 为一组选定的商品计算包含物流费的预估总成本。
    - Request Body:
    - JSON
{
  "supplierProductIds": ["prod_1688_x1y2z3", "prod_1688_a4b5c6"],
  "logisticsQuery": "空运，10天到货"
}
    - Success Response (200 OK):
    - JSON
{
  "costResults": [
    {
      "supplierProductId": "prod_1688_x1y2z3",
      "title": "厂家直供TWS蓝牙耳机...",
      "purchasePrice": "35.50",
      "estimatedLogisticsCost": "15.00",
      "estimatedTotalCost": "50.50",
      "logisticsRecommendation": "因时效要求10天内，已匹配 'XXX专线空运' 渠道。"
    },
    // ... other products
  ]
}

2.4 确认选品并转入运营

- 前端实现:
  - 用户在成本核算后的列表中，选择最终的一款商品。
  - 点击“就选这个，去运营”按钮，调用 [API 2.1]。
  - 成功后，使用返回的 operationTaskId 跳转到运营助手页面 (/operations/{operationTaskId} router)。
- 后端 API (Workflow II的起点):
  - [API 2.1] 创建运营任务
    - Endpoint: POST /api/v1/operation-tasks
    - 描述: 基于最终选定的商品，创建一个新的运营任务。
    - Request Body:
    - JSON
{
  "finalSupplierProductId": "prod_1688_x1y2z3"
}
    - Success Response (201 Created):
    - JSON
{
  "operationTaskId": "task_ops_e5f6g7h8",
  "status": "DRAFT", // 运营任务状态: DRAFT -> TRANSLATING -> COMPLETED"message": "运营任务已创建"
}

3. 核心工作流II: AI运营助手 - 技术实现

3.1 获取运营素材与AI优化

- 前端实现:
  - 运营页面加载时，从URL中获取operationTaskId。
  - 调用 [API 2.2] 获取任务详情。
  - 页面展示一个双栏编辑器：左侧显示originalContent，右侧显示optimizedContent。右侧内容可编辑。
  - 如果optimizedContent初始为null，则右侧显示加载状态，并轮询 [API 2.2] 直到获取到内容。
- 后端 API:
  - [API 2.2] 获取/刷新运营任务详情
    - Endpoint: GET /api/v1/operation-tasks/{taskId}
    - 描述: 获取运营任务的详细信息，包括原始素材、AI优化内容和翻译内容。
    - Success Response (200 OK):
    - JSON
{
  "operationTaskId": "task_ops_e5f6g7h8",
  "status": "DRAFT",
  "sourceProduct": { /* ...商品原始信息... */ },
  "content": {
    "title_zh": "原1688标题",
    "description_zh": "原1688描述...",
    "optimized_title_zh": "【AI优化后】爆款TWS降噪耳机...", // 可能初始为null"optimized_description_zh": "【AI优化后】探索音乐的纯粹...", // 可能初始为null"translations": { // 可能初始为null或空对象"ru": {
        "title": "...",
        "description": "..."
      }
    }
  }
}
    - 后端逻辑:
      1. 当 [API 2.1] 被调用时，后端异步触发AI优化流程。
      2. 此API负责从数据库读取任务的最新状态。

3.2 内容审核与修改

- 前端实现:
  - 用户在右侧编辑器修改文案后，可以点击“提交修改建议”按钮。
  - 提供一个输入框让用户写修改意见。
  - 点击按钮后，将整个optimizedContent和用户的revisionRequest文本发送到 [API 2.3]。
- 后端 API:
  - [API 2.3] 请求AI修改文案
    - Endpoint: PUT /api/v1/operation-tasks/{taskId}/content
    - 描述: 根据用户的反馈，让AI重新优化文案。
    - Request Body:
    - JSON
{
  "currentTitle": "用户修改后的标题",
  "currentDescription": "用户修改后的描述",
  "revisionRequest": "请重点突出电池续航能力"
}
    - Success Response (200 OK):
      - 返回与 [API 2.2] 结构相同的最新任务对象。

3.3 内容翻译

- 前端实现:
  - 提供语言选择下拉框（如俄语、英语）。
  - 用户选择一个语言后，调用 [API 2.4]。
  - 界面显示加载状态，并开始轮询 [API 2.2]，直到translations字段中出现对应语言的数据，然后渲染出来。
- 后端 API:
  - [API 2.4] 翻译内容
    - Endpoint: POST /api/v1/operation-tasks/{taskId}/translate
    - 描述: 将已确认的中文文案翻译成指定语言。
    - Request Body:
    - JSON
{
  "targetLanguage": "ru" // ISO 639-1 code
}
    - Success Response (202 Accepted):
    - JSON
{
  "message": "翻译任务已启动"
}

3.4 上传到OZON

- 前端实现:
  - 提供一个“一键上传至OZON”按钮。
  - 点击后，调用 [API 2.5]。
  - 根据返回结果，显示“上传成功”或“上传失败：[错误信息]”的提示。
- 后端 API:
  - [API 2.5] 上传商品到OZON
    - Endpoint: POST /api/v1/operation-tasks/{taskId}/upload-to-ozon
    - 描述: 将最终内容发布到用户的OZON店铺。
    - Request Body: (可选，如果需要指定最终语言)
    - JSON
{
  "languageToUpload": "ru"
}
    - Success Response (200 OK):
    - JSON
{
  "status": "SUCCESS",
  "ozonProductId": "ozon_prod_98765",
  "message": "商品已成功上传至OZON"
}
    - Error Response (400/500):
    - JSON
{
  "status": "FAILED",
  "message": "OZON API返回错误：无效的类目ID"
}

4. 浏览器插件通信规约

4.1 后端 -> 插件 (指令下发)

- 机制: 推荐使用WebSocket。后端作为Server，插件作为Client。插件启动后连接后端WebSocket服务。
- 指令格式: 后端向插件发送JSON消息。
- JSON
{
  "command": "scrape_1688",
  "payload": {
    "taskId": "task_sel_a1b2c3d4",
    "searchKeywords": ["беспроводные наушники", "наушники TWS bluetooth 5.3"]
  }
}

4.2 插件 -> 后端 (数据回传)

- 机制: 插件通过标准的HTTP POST请求将结果发送给后端一个专用的回调接口。
- Endpoint: POST /api/v1/scraper/callback
- 描述: 插件专用，用于回传爬取到的数据。
- Request Body:
- JSON
{
  "taskId": "task_sel_a1b2c3d4",
  "status": "SUCCESS", // SUCCESS or FAILED"data": [
    {
      "title": "...", "price": "...", "imageUrl": "...", "productUrl": "..."
    }
  ],
  "errorMessage": null // 如果失败，则填写错误信息
}
